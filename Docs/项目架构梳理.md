## 摘要

AntiFraudStorm 是一个基于 **Unity 2022.3 + URP** 的 3D 反诈题材校园互动游戏/科普课件。整体结构可以概括为：

> **一个校园 Hub（School） + 一条主线任务 + 两个 Additive 子场景小游戏 + 一套相机取证/日志系统。**

玩家以第三人称在“蓝湾大学”校园中探索，跟随主线“办理入学注册”进入虚拟桌面完成注册；同时可以拍摄校园中的诈骗传单收集反诈日志，接近被诈骗话术“蛊惑”的学生进入三路塔防式的“反诈防线”。

## 1. 项目定位与功能全景

### 1.1 项目定位

- **题材**：校园反诈科普，覆盖刷单返利、虚假投资、冒充公检法、冒充客服、网络贷款、买卖两卡、境外来电、游戏交易、跨境赌博、校园贷等话术。
- **形态**：3D 校园探索 + 任务引导 + 叙事型桌面交互 + 两个独立小游戏。
- **平台**：当前按 PC 键鼠设计（旧版 Input Manager，光标锁定/解锁、OS 中文字体回退）。
- **目标体验**：让玩家在“办理入学—识别钓鱼—完成注册—拍摄证据—抵御诈骗”的完整链路中学习反诈知识。

## 4. 总体架构

```text
School（Hub，Build 0）
├─ Player（3C）
│   ├─ C ──► PlayerHandheldCamera ──► CameraViewfinder
│   └─ E ──► QuestZoneTrigger ──► QuestService
│                                   ├─► QuestHudBinder ──► GameplayHud
│                                   └─► CampusComputerSession
│                                         ├─ Additive ──► FakeWindowsDesktop
│                                         └─ Additive ──► Anti-Scam Cortex
├─ SchoolDigitalHumanSpawner
│   └─► DigitalHumanWalker / DigitalHumanPatrol
│         └─► BewitchedStudentPortal ── E ──► Anti-Scam Cortex
└─ AntiFraudEvidenceSystem ──► GameplayHud（反诈日志）
```

- **Hub 常驻**：`School` 承载玩家、任务、NPC、取证和 HUD，是唯一长期存在的场景。
- **子场景 Additive 加载**：`FakeWindowsDesktop`（电脑/注册）和 `Anti-Scam Cortex`（防线）不替换校园，而是叠加加载；进入时校园根节点整体 `SetActive(false)`（`QuestSystem` 除外），退出时唤醒。
- **服务单例 + 事件**：`QuestService`、`CampusComputerSession`、`GameplayHudController`、`CameraViewfinderController`、`AntiFraudEvidenceSystem`、`DesktopCharacterPortraits` 都通过静态 `Instance` 跨场景访问。

## 5. 主要流程

### 5.1 主线“办理入学注册”

1. `School` 启动时，`QuestService` 在 `Awake` 中自动激活 `Q_EnrollRegistration`，避免与 `QuestZoneTrigger.Start()` 产生显隐竞态。
2. 注册点上的 `QuestZoneTrigger` 显示标记，玩家进入触发区后出现“按下 E 键”提示。
3. 玩家按 E，`CampusComputerSession.EnterComputer()` 推近相机、淡黑、休眠校园根节点，并 Additive 加载 `FakeWindowsDesktop`。
4. `FakeWindowsDesktop` 中通过虚拟桌面完成注册：选官网 → 进入学校页 → “开学注册” → 3D 闯关 → 成功。
5. `VirtualDesktopController` 完成注册后调用 `QuestService.CompleteActiveQuest()`，HUD 任务条清空，任务标记隐藏。
6. 玩家点“返回校园”，`CampusComputerSession.ReturnToCampus()` 卸载 `FakeWindowsDesktop`、唤醒校园、恢复相机，流程闭环。

### 5.2 相机取证

1. 按 C，`PlayerHandheldCamera` 播放取出动画，把道具相机从 Hips 世界插值到右手，进入第一人称并显示取景器。
2. `AntiFraudEvidenceSystem.Update` 在“举相机、非忙碌、光标锁定、按下左键”时，从屏幕中心 Raycast 6 米。
3. 命中 `scam_flyer_v2_*` 传单后触发拍照闪光，写入 `CapturedEntries`，并调用 `GameplayHudController.ShowEvidenceCaptured()`。
4. 点 HUD 的“日志”按钮打开两页式反诈日志；5 张传单共 3 页。

### 5.3 反诈防线

1. 靠近被蛊惑的 NPC（2.8 米内）出现“按 E 进入反诈骗防线”的 3D 提示。
2. `BewitchedStudentPortal` 调用 `CampusComputerSession.EnterDangerScene()`，加载 `Anti-Scam Cortex`。
3. `AntiFraudDefenseGame` 运行时创建玩家、HUD、炮塔、敌人和世界文字。
4. 鼠标点击放置反诈工具炮塔，炮塔自动索敌开火；三路敌人不断来袭。
5. 敌人近战/远程命中分别扣 85/55 金币；`WaveLoop` 无限循环。

### 5.4 返回校园

`FakeWindowsDesktop` 的“返回校园”走 `CampusComputerSession.ReturnToCampus()`：卸载 `FakeWindowsDesktop`、唤醒校园根节点、恢复相机状态、重建 NPC 的 Animancer 状态、淡入。

> `Anti-Scam Cortex` 目前没有对应出口：`ReturnToCampus()` 只处理电脑场景，`_inDanger` 进入后不会复位。

## 6. 核心模块拆解

### 6.1 3C 与相机

`ThirdPersonPlayerController` 以 `[DefaultExecutionOrder(-10)]` 统一编排：

- `PlayerInputReader`：旧输入封装，WASD/方向键、鼠标视角、Shift 冲刺、Space 跳跃、V 切视角、C 掏相机、E 交互、Alt 呼出鼠标、Esc 解锁。
- `ThirdPersonMotor`：CharacterController 移动，相机相对方向、加速、旋转、跳跃、重力。
- `ThirdPersonSpringArm`：第三人称/第一人称/越肩三套 `ModeSettings`，含相机碰撞、FOV、第一人称隐藏玩家模型。
- `PlayerAnimancerLocomotion`：Idle/Walk/Run/Jump 离散状态，无混合树，Walk/Run 用独立倍速。
- `PlayerHandheldCamera`：C 键独立状态机，Hips 待机 → 世界插值到右手 → 第一人称 + 取景器 → 收起动画结束后回到 Hips。

`CampusComputerSession.IsFrozen` 会冻结移动和视角；`PlayerHandheldCamera` 忙碌时会屏蔽移动/冲刺/跳跃。

### 6.2 任务系统

- [QuestDefinition.cs](../Assets/Scripts/Quest/QuestDefinition.cs#L6)：ScriptableObject，定义 `id`、`tagLabel`、`title`、`nextQuestId`、标记 prefab、标记缩放、触发半径。
- [QuestService.cs](../Assets/Scripts/Quest/QuestService.cs#L11)：维护 `Inactive/Active/Completed` 状态和当前目标，抛出 `QuestStarted`、`QuestChanged`、`QuestCompleted`、`QuestPointEntered` 事件；完成时按 `NextQuestId` 自动接续。
- [QuestZoneTrigger.cs](../Assets/Scripts/Quest/QuestZoneTrigger.cs#L12)：球形触发、标记显隐（避免直接禁用自身导致事件断订）、E 键交互、可选的“进入即完成”。
- [QuestHudBinder.cs](../Assets/Scripts/Quest/QuestHudBinder.cs#L9)：每 0.15 秒把任务标题和距离推给 HUD。
- [QuestInteractPrompt.cs](../Assets/Scripts/Quest/QuestInteractPrompt.cs#L8)：世界空间 3D TextMesh 广告牌提示。

当前只有 `enroll_registration` 一个任务，`nextQuestId` 为空，因此完成后没有后续任务。

### 6.3 场景编排

[CampusComputerSession.cs](../Assets/Scripts/SceneFlow/CampusComputerSession.cs#L96) 是跨场景核心：

1. 记录主相机位置/FOV → 推近相机、缩小 FOV；
2. 淡黑 → 启用 `DisplayHoldCamera`（纯黑保底相机）；
3. `SleepCampusRoots()` 把校园根节点设为不激活，但跳过包含 `CampusComputerSession` 的 `QuestSystem`；
4. 禁用校园相机 → `LoadSceneAsync(..., Additive)`；
5. 等待目标场景出现可用相机（最多 2 秒），必要时兜底启用；
6. 淡入。退出时反向执行，并调用 `DigitalHumanWalker.RestoreAfterCampusActivation()` 重建被休眠破坏的 Animancer 状态。

`CampusComputerSession` 暴露 `EnterComputer()`、`EnterDangerScene()`、`ReturnToCampus()`、`IsFrozen`、`IsInComputer`、`IsInDanger`，是 UI 与场景切换之间的唯一入口。

### 6.4 FakeWindowsDesktop：虚拟桌面与注册闯关

[VirtualDesktopController.cs](../Assets/UI/Scripts/VirtualDesktopController.cs#L18) 用 UI Toolkit 页面状态机串起：

```text
桌面 → 浏览器 → 地址下拉
├─ 选择官网 ──► 学校页 ──► 3D 注册闯关 ──► 成功
├─ 选择仿冒站 ──► 高危提示 + 扣金币
└─ 假助学金通知 ──► 钓鱼链接 ──► 高危提示 + 扣金币
```

- 第一次点地址栏会触发小偷立绘出场，并让 4 枚“钓鱼网址”飞入下拉框，随后打乱顺序；
- 选错扣当前金币的 15%，进入高危提示页；选对 2 秒后弹出假助学金通知，点链接同样进入钓鱼失败页；
- 官网的“开学注册”进入 [Enrollment3DChallengeController.cs](../Assets/Scripts/Minigame/Enrollment3DChallengeController.cs#L11)：运行时搭 6 块平台、2 个巡逻敌人、终点旗，A/D + 空格横版跑酷，完成回调后 `CompleteActiveQuest()`。

另有一套 4 步表单向导（学号 → 邮箱验证码 → 缴费 6800 → 完成），但 `OpenEnrollWizard()` 没有任何调用，实际不可达。

### 6.5 Anti-Scam Cortex：反诈防线塔防

[AntiFraudDefenseGame.cs](../Assets/Scripts/Minigame/AntiFraudDefenseGame.cs#L15) 在运行时创建玩家、HUD、炮塔、敌人和世界文字：

- 10 种反诈工具对应 10 种诈骗话术，命中分三档：精准 60 / 同类 28 / 不匹配 10；
- 炮塔自动索敌，1.2 秒开火，12 秒后消失，放置冷却 4.5 秒；
- 敌人分三路，每波 3 个，第 0 路为远程 `Gloom`，其余为近战 `Wraith` / `Grim Reaper`；
- 初始金币 1280，近战/远程攻击分别扣 85/55；
- `WaveLoop` 是 `while(true)`，没有胜负条件。

关键子类：

| 类 | 职责 |
|---|---|
| `FraudToolTurret` | 自动索敌、按工具类型发射弹道、生命周期结束缩放消失 |
| `DefenseEnemy` | 单车道推进、攻击冷却、HP/死亡、世界血条 |
| `DefenseProjectile` | 轻型追踪弹，命中回调，玩家/敌人共用 |
| `AntiFraudDefenseGame` | 波次、召唤、炮塔放置、伤害结算、金币损失、HUD/FX |

### 6.6 NPC、取证与立绘

- [SchoolDigitalHumanSpawner.cs](../Assets/Scripts/Navigation/SchoolDigitalHumanSpawner.cs#L46)：等 A\* 图扫描完成后生成 10 个随机外观 NPC；前 3 个直接落在 scam 点并进入蛊惑状态，其余 7 个在 `Floor1 Navigation Points` 巡逻。
- [DigitalHumanWalker.cs](../Assets/Scripts/Navigation/DigitalHumanWalker.cs#L12)：根据 RichAI 速度切走/待机；蛊惑时切 `Face_A3`、播 agonize 动画、头顶挂粒子。
- [BewitchedStudentPortal.cs](../Assets/Scripts/Navigation/BewitchedStudentPortal.cs#L30)：2.8 米内显示 TextMesh 提示，按 E 进入 `Anti-Scam Cortex`。
- [AntiFraudEvidenceSystem.cs](../Assets/Scripts/Evidence/AntiFraudEvidenceSystem.cs#L22)：通过 `RuntimeInitializeOnLoadMethod` 自动在 `School` 场景引导，扫描 5 张 `scam_flyer_v2_*` 传单；`EvidenceFlyer` 按编号映射标题和摘要。
- [DesktopCharacterPortraits.cs](../Assets/Scripts/Portrait/DesktopCharacterPortraits.cs#L12)：用独立相机 + 512×512 RenderTexture 把 3D 角色渲染成桌面立绘；小偷出场时播放警报飞散特效，答对/答错播放不同反馈动画。

## 8. 架构特点

- **场景组合而非场景替换**：Hub + Additive 子场景，切换时“休眠校园”而不是销毁，保留任务/NPC/玩家状态。
- **服务单例 + C# 事件**：跨场景通信成本低，适合当前规模；代价是隐式依赖较多。
- **UI 双轨**：叙事型界面用 UI Toolkit（虚拟桌面、HUD、取景器），战斗型界面用 uGUI 运行时生成（塔防 HUD、血条、伤害飘字），避免场景里堆大量 UI 预制体。
- **3D 立绘用 RenderTexture**：把角色渲染到纹理再贴到 UI，兼顾 3D 表现和 UI 布局。
- **内容高度硬编码**：任务之外，工具名、诈骗名、伤害、网址、文案都写在 Controller 数组里，没有配表/本地化。

## 9. 完成度与风险

### 9.1 功能缺口

1. **主菜单没有接入启动流程**：[MainMenuController.cs](../Assets/UI/Scripts/MainMenuController.cs#L44) 的“开始/设置”只打 `Debug.Log`，没有 `LoadScene("School")`；而 Build 首场景是 `School`，所以实际运行会直接进校园。
2. **`Anti-Scam Cortex` 没有退出和胜负**：[CampusComputerSession.ReturnToCampus()](../Assets/Scripts/SceneFlow/CampusComputerSession.cs#L89) 只处理电脑场景，`_inDanger` 从不复位，塔防 `WaveLoop` 无限循环；金币扣到 0 也没有失败结算。
3. **FakeWindowsDesktop 表单向导不可达**：[OpenEnrollWizard()](../Assets/UI/Scripts/VirtualDesktopController.cs#L979) 没有调用点，学号/邮箱/缴费页面只是保留代码。
4. **任务与存档单薄**：只有一条任务，无 `PlayerPrefs`/存档，完成即结束；HUD 的地图/AI/手机/设置按钮均为占位日志。
5. **无暂停、设置、音量等系统层**；`Anti-Scam Cortex` 也没有暂停菜单。

### 9.2 工程风险

- 无自研 asmdef，全部运行时代码在 `Assembly-CSharp`，模块边界靠命名空间和目录维持。
- 单例与 UI/玩法双向依赖较多（如 Evidence → HUD、Minigame → QuestService），后续拆分需要先收口服务接口。
- 文本、数值、URL、骨骼名均硬编码；[PlayerThirdPersonSetup.cs](../Assets/Scripts/Player/Editor/PlayerThirdPersonSetup.cs#L154) 仍在查找已不存在的 `targetOffset` / `defaultDistance` 字段，运行该编辑器菜单会空引用。
- `AntiFraudEvidenceSystem.Update` 每帧 `FindObjectOfType<PlayerHandheldCamera>()`；角色剥离逻辑在 `Enrollment3DChallengeController` 和 `DesktopCharacterPortraits` 中重复。
- `PlayerHandheldCamera` 依赖 `QuickRigCharacter2_RightHand` / `QuickRigCharacter2_Hips` 等硬编码骨骼名，替换角色模型时需要同步修改。
